# 气象插值（Kriging + WebGL）实现分析

> 对应目录：`src/views/cesiumLast/component/water/weatherSample`

## 一、总体架构

该模块实现了一套**基于克里金（Kriging）插值 + WebGL 并行计算 + Cesium 渲染**的气象数据时空可视化方案。

核心特点：
- **WebWorker 离线计算**：将 Kriging 训练和网格插值放到 Worker 线程，避免阻塞主线程
- **WebGL GPU 加速**：利用 Fragment Shader 对每个网格像素并行执行 Kriging 预测，替代传统 CPU 逐点计算
- **时间轴驱动**：支持多时间帧数据，帧间线性过渡，带 LRU 缓存和预加载
- **Cesium GroundPrimitive 贴地渲染**：自定义 Material Shader，双纹理混合实现平滑动画

## 三、实现步骤详解

### 步骤 1：数据准备

每个 `data*/index.ts` 导出一个 `krigingDataMeta` 对象，包含：

- **`points`**：观测站经纬度数组 `[[lon, lat], ...]`
- **`data`**：时间序列数据，每项 `{time: 时间戳, value: 各站点观测值数组}`
- **`startTime / endTime / interval`**：定义时间轴范围和步长
- **`colorMap.breaks`**：颜色分级映射，如降雨量 0~10mm 绿色、10~25mm 蓝色等
- **`rings`**（可选）：裁剪多边形顶点，用于限定插值区域

示例（`data6/index.ts`）：
```ts
const points = [
    [112.109243, 29.995875],
    [112.0131747, 29.98688967],
    // ... 共 15 个站点
];
const data = new Array(frames).fill('').map((_, timeIndex) => ({
    time: timeIndex * interval + startTime,
    value: new Array(points.length).fill(0).map(() => Math.random()),
}));
```

### 步骤 2：初始化 KrigingPrimitive

在 `index.vue` 的 `addKrigingPrimitive()` 中创建 `KrigingPrimitive` 实例：

```ts
prePrimitive = new KrigingPrimitive({
    points: krigingDataMeta.points,
    rings: krigingDataMeta.rings,
    minSideSize: 200,          // 网格最短边像素数
    timeRange: {min, max, interval},
    colorMapping: krigingDataMeta.colorMap.breaks,
    rainDataGetter(t) {        // 按时间戳获取观测值
        return Promise.resolve(...)
    },
})
```

构造函数内部完成以下初始化：

1. **计算网格参数**：根据观测点的外接矩形和 `minSideSize`，计算 `cellSize`、`cols`、`rows`
2. **创建 Web Worker**：`new MyWorker()`，用于后台执行 Kriging 计算
3. **添加 Cesium 可视化元素**：
   - `GroundPrimitive`：主渲染体，使用自定义 Shader Material
   - `Grid`：辅助网格线
   - `PointPrimitiveCollection` + `LabelCollection`：观测点标记和实时数值标签
4. **自动飞行**：相机飞至数据外接矩形

### 步骤 3：Worker 中的 Kriging 训练与网格生成

当需要某时刻的插值结果时，调用流程如下：

#### 3.1 主线程发起请求

`KrigingPrimitive.startLoad()` 将任务送入 Worker：

```ts
this._rainDataGetter(timeFrame)
    .then(data => this.gerenate({...this._gernerateObj, data}))
```

`gerenate()` 通过 `postMessage` 把数据发给 Worker，并返回 Promise。

#### 3.2 Worker 接收并处理（`worker.ts`）

```ts
const variogram = train(data, xs, ys, 'exponential', 0, 10);
const packedImagebitmap = await generate_WEBGL({
    variogram, llCorner, cellSize, gridSize, packValueRange,
    outputFormat: 'packed-imagebitmap'
});
```

分为两个阶段：

**阶段 A：`train()` —— 变差函数训练**（`kriging.ts`）

输入：观测值 `t[]`、坐标 `x[]`、`y[]`、模型类型（`exponential`）、`sigma2=0`、`alpha=10`

执行过程：
1. 计算所有观测点对的距离和半方差（`distance[k] = [距离, |差值|]`）
2. 按距离分箱（lag binning），最多 30 个 lag
3. 对每个 lag 计算平均距离和平均半方差
4. **最小二乘拟合**：将 lag 距离代入模型基函数，拟合出变差函数参数：
   - `nugget`（块金值）
   - `sill`（基台值）
   - `range`（变程）
5. 构建 **Gram 矩阵 K**：`K[i,j] = γ(distance(i,j))`，即两点间变差函数值
6. 加入正则项 `K + σ²I`，求逆得到 `K⁻¹`
7. 计算 `M = K⁻¹ · t`（权重与观测值的组合向量）
8. 返回 `Variogram` 对象，包含 `M`、`x`、`y`、模型参数

**阶段 B：`generate_WEBGL()` —— GPU 并行插值**（`webgl/generate.ts`）

核心思想：把每个网格点当成一个像素，在 Fragment Shader 中并行执行 Kriging `predict()`。

执行过程：
1. **创建变差函数纹理**（`createVariogramObject`）：
   - 将 `M[i]`、`x[i]`、`y[i]` 打包成 RGBA Float32 纹理
   - 每个像素存储一个观测点的信息
   - 最多支持 1024 个观测点
2. **设置 Shader Uniform / UBO**：
   - `u_gridInfo`：网格左下角坐标 + cellSize
   - `u_dimension`：观测点数量
   - `u_variogramParam`：`[nugget, range, sill, A]`
   - `u_model`：模型类型编码（1=gaussian, 2=exponential, 3=spherical）
   - `u_packValueRange`：输出值归一化范围
3. **渲染全屏四边形**：
   - `gl_FragCoord.xy` 即网格像素坐标
   - Shader 中将像素坐标反算为地理坐标：`inputCoord = gl_FragCoord.xy * cellSize + llCorner`
4. **Fragment Shader 核心逻辑**（`glsl_fs_main`）：
   ```glsl
   for(int i = 0; i < 1024; i++){
       if(i == max_i) break;
       vec3 mxy = lookup(float(i));  // 从纹理读取 M[i], x[i], y[i]
       sum += modelValue(u_model, hypot(inputCoord - xy[i]), variogram) * mxy[0];
   }
   ```
   - `lookup()`：从变差函数纹理中按索引采样
   - `modelValue()`：根据模型类型计算变差函数值 `γ(h)`
   - 最后 `sum` 即为该网格点的 Kriging 预测值
5. **输出打包**：
   - 将预测值归一化到 `[0, 1]`，使用 RGB 打包编码（`packNormalizeFloatToRGB`）
   - 输出到 `ImageBitmap`（通过 `OffscreenCanvas.transferToImageBitmap()`）

#### 3.3 主线程接收结果

Worker 返回 `{packedImagebitmap, trainTime, generateTime}`，主线程：
- 存入 `LRUCache`（最多缓存 32 帧，超出时自动 `close()` 旧的 ImageBitmap）
- 调用 `updateUniforms()` 更新 Cesium Material 纹理

### 步骤 4：Cesium 渲染与动画

#### 4.1 GroundPrimitive + 自定义 Material

```ts
new Cesium.GroundPrimitive({
    geometryInstances: new Cesium.GeometryInstance({
        geometry: new Cesium.PolygonGeometry({
            polygonHierarchy: new Cesium.PolygonHierarchy(
                Cesium.Cartesian3.fromDegreesArray(this._rings.flat())
            ),
        }),
    }),
    appearance: new Cesium.Appearance({
        material: new Cesium.Material({
            fabric: {
                type: 'KrigingRain',
                uniforms: {
                    u_image1: 'czm_defaultImage',
                    u_image2: 'czm_defaultImage',
                    u_unpackRange: Cartesian2,
                    u_imageSize: Cartesian2,
                    u_percent: -1
                },
                source: `...GLSL...`
            }
        })
    })
})
```

Material Shader 关键逻辑：
- 接收两张纹理 `u_image1`（前一帧）、`u_image2`（后一帧）
- `u_percent`：混合权重（0~1），`-1` 表示不显示
- `lookupValue()`：手动实现**双线性插值**，提高纹理采样精度
- `getColor()`：根据分级颜色映射将数值转为 RGB
- `mix(rain1, rain2, u_percent)`：两帧间线性过渡

#### 4.2 时间轴驱动

`setTime(t)` 的执行流程：

1. 根据时间 `t` 找到前后两个关键帧索引 `beforeIndex`、`afterIndex`
2. 计算混合比例：`percent = (t - beforeTime) / (afterTime - beforeTime)`
3. 将前后帧及后续 5 帧加入加载队列
4. `startLoad()` 串行异步加载（通过 Promise 链保证顺序）
5. 当两帧都在 `LRUCache` 中时，`updateUniforms()` 设置：
   ```ts
   this._uniforms.u_image1 = this._cache.get(beforeTime);
   this._uniforms.u_image2 = this._cache.get(afterTime);
   this._uniforms.u_percent = percent;
   ```
6. 同时更新 `LabelCollection` 中各站点的实时数值

## 四、关键技术细节

### 4.1 为什么用 WebGL 做 Kriging 预测？

传统 Kriging 对每个网格点需遍历所有观测点计算 `γ(h)` 并加权求和，时间复杂度 `O(n × cols × rows)`。

本方案将其移到 GPU：
- 每个网格点 = 一个像素
- Fragment Shader 内循环遍历观测点（最多 1024）
- GPU 成百上千个像素并行执行，速度远超 CPU

实测在 Worker 中返回的日志：`train: ~Xms, generate: ~Xms`，网格生成毫秒级完成。

### 4.2 数据打包与精度

预测值范围可能很大（如降雨量 0~1000mm），直接存 Float Texture 兼容性差。方案采用：
- **归一化**：`(value - min) / (max - min)` 映射到 `[0, 1]`
- **RGB 打包**：用 3 个字节（24bit）存储小数，精度约 `1/16,777,216`
- Shader 中 `unpackRGBToNormalizeFloat()` 解码，再 `mix(unpackRange.x, unpackRange.y, normalized)` 还原真实值

### 4.3 Worker + LRUCache + 预加载

- **Worker**：训练和生成完全在后台线程，主线程只负责 Cesium 渲染
- **LRUCache**：缓存 32 帧 `ImageBitmap`，避免重复计算，自动释放旧纹理内存
- **预加载**：每次加载当前帧时，顺便把后续 5 帧加入队列，保证播放流畅
- **串行加载**：`startLoad()` 使用单任务队列，避免 Worker 同时处理多个请求导致拥塞

### 4.4 WebGL1 / WebGL2 兼容

- 优先使用 WebGL2，支持 `RGBA32F` 纹理、`EXT_color_buffer_float`、UBO
- WebGL1 回退：使用 `OES_texture_float` 扩展，普通 uniform 传参
- Shader 通过前缀宏自动适配（`#define webgl2`、`#define texture2D texture`）

### 4.5 颜色映射的两种方案

1. **硬编码 GLSL**：在 `index.vue` 中直接写 `if(v <= 10.0) return ivec3(...)`，适合固定分级
2. **纹理查找表**：将分级信息编码成 Float32 纹理，Shader 中用二分查找（`mappingColor`），适合动态分级

当前实现默认使用硬编码，但保留了纹理查找的完整代码。

## 五、调用链路图

```
index.vue (主线程)
    │
    ├─► new KrigingPrimitive()
    │       ├─ 计算网格参数 (cols, rows, cellSize)
    │       ├─ 创建 Worker
    │       ├─ 添加 Cesium GroundPrimitive + Grid + Labels
    │       └─ setTime(min) ──┐
    │                         ▼
    │                   startLoad()
    │                         │
    │                         ▼
    │                   Worker.postMessage({data, id})
    │                         │
    ▼                         ▼
Cesium 渲染 ◄─────── Worker.onmessage({packedImagebitmap})
    │
    │   (时间轴播放时)
    │   setTime(t) → 计算 before/after 帧 + percent
    │   updateUniforms() → u_image1 / u_image2 / u_percent
    │
    ▼
Cesium Material Shader
    ├─ lookupValue(uv, u_image1) → bilinear sample → rain1
    ├─ lookupValue(uv, u_image2) → bilinear sample → rain2
    ├─ mix(rain1, rain2, u_percent) → rain
    └─ getColor(rain) → diffuse color
```
